# Epic Light Launcher (Omega Launcher)

Launcher desktop feito com **Tauri + React + TypeScript** para consumir dados da conta Epic via **Legendary CLI** e exibir recursos da Epic Store (destaques, jogos gratis, promocoes e busca de catalogo).

## Proposito do projeto

O projeto existe para oferecer uma experiencia leve e centralizada para:

- visualizar a biblioteca da Epic (com paginacao e busca);
- consultar detalhes de jogos;
- ver perfil, wishlist e amigos;
- acompanhar jogos gratis e promocoes da Epic Store;
- configurar cookie e user-agent para contornar bloqueios de acesso do GraphQL da Store.

## Stack

- Frontend: React 19, React Router, Vite, TypeScript, TailwindCSS
- Desktop/runtime: Tauri v2 (Rust)
- Integracoes:
  - `src-tauri/bin/legendary.exe` (Legendary CLI)
  - APIs Epic GraphQL e Epic Store

Para carregar biblioteca e dados da conta, autentique o Legendary:

```powershell

```

Depois rode:

```bash
npm run tauri dev
```

Se a sessao expirar, a tela de biblioteca permite reautenticar.

## Configuracao da Epic Store (cookie e user-agent)

Alguns endpoints da Epic Store podem ser bloqueados por Cloudflare. O app possui tela **Settings** para salvar:

- Cookie completo da request para `https://store.epicgames.com/graphql`
- User-Agent usado nessa mesma request

Arquivos locais usados pelo app:

- Cookie: `%AppData%/epic-light-launcher/store_cookie.txt`
- User-Agent: `%AppData%/epic-light-launcher/store_user_agent.txt`

## Variaveis de ambiente uteis

- `EPIC_GRAPHQL_PROXY`: proxy para chamadas GraphQL da conta
- `EPIC_STORE_PROXY`: proxy para chamadas da Store
- `EPIC_GRAPHQL_DEBUG=1`: logs detalhados do GraphQL
- `EPIC_STORE_DEBUG=1`: logs detalhados da Store
- `EPIC_STORE_COOKIE`: cookie da Store direto por env
- `EPIC_STORE_COOKIE_FILE`: caminho customizado para arquivo de cookie
- `EPIC_USER_AGENT`: sobrescreve user-agent padrao

Exemplo no PowerShell:

```powershell
$env:EPIC_GRAPHQL_PROXY="http://seu-proxy:porta"
npm run tauri dev
```

## Sync opcional (Fase 2 - base pronta)

O app agora possui adapter Supabase com fallback local e estrategia de conflito por `updatedAt`.

- Configuracao em `Settings`:
  - provider (`local` ou `supabase`)
  - `Supabase URL`
  - `Supabase Anon Key`
  - login cloud (`Entrar cloud`) via Supabase Auth
  - flag de auto sync
  - botao `Sincronizar agora` (manual)
- Seguranca de sessao cloud:
  - token de sessao fica no cofre seguro do sistema operacional (Credential Manager/Keychain);
  - `localStorage` guarda apenas configuracoes nao sensiveis (URL, anon key, flags);
  - refresh de sessao e automatico antes do vencimento.
- Com `auto sync` ligado:
  - leitura faz merge local/cloud e escolhe o registro mais recente;
  - escrita salva local e replica para cloud;
  - em falha de rede/cloud, fallback automatico para SQLite local.

### SQL seguro necessario no Supabase (com RLS)

Crie a tabela abaixo no SQL Editor do projeto:

```sql
create table if not exists public.omega_user_game_data (
  id bigint generated by default as identity primary key,
  user_id uuid not null references auth.users(id) on delete cascade,
  app_name text not null,
  custom_tags jsonb not null default '[]'::jsonb,
  notes text not null default '',
  playtime_minutes integer not null default 0 check (playtime_minutes >= 0),
  rating integer null check (rating between 1 and 5),
  updated_at timestamptz not null default now(),
  unique (user_id, app_name)
);

alter table public.omega_user_game_data enable row level security;

revoke all on table public.omega_user_game_data from anon;
grant select, insert, update, delete on table public.omega_user_game_data to authenticated;
grant usage, select on sequence public.omega_user_game_data_id_seq to authenticated;

create policy if not exists "read_own_game_data"
on public.omega_user_game_data
for select
to authenticated
using (auth.uid() = user_id);

create policy if not exists "insert_own_game_data"
on public.omega_user_game_data
for insert
to authenticated
with check (auth.uid() = user_id);

create policy if not exists "update_own_game_data"
on public.omega_user_game_data
for update
to authenticated
using (auth.uid() = user_id)
with check (auth.uid() = user_id);

create policy if not exists "delete_own_game_data"
on public.omega_user_game_data
for delete
to authenticated
using (auth.uid() = user_id);
```

Observacao: sem autenticar no Supabase Auth, o app nao ativa escrita/leitura cloud e permanece em fallback local.

## Troubleshooting rapido

### Biblioteca nao carrega / erro 403

1. Reautentique o Legendary:
   ```powershell
   .\src-tauri\bin\legendary.exe auth
   ```
2. Reinicie o app.

### Wishlist/Amigos vazios ou Store bloqueada

1. Configure Cookie e User-Agent na tela **Settings**.
2. Teste com proxy (`EPIC_GRAPHQL_PROXY` / `EPIC_STORE_PROXY`) se sua rede bloquear.
3. Ative debug:
   ```powershell
   $env:EPIC_GRAPHQL_DEBUG="1"
   $env:EPIC_STORE_DEBUG="1"
   npm run tauri dev
   ```

## Observacoes

- O projeto esta preparado principalmente para Windows (usa `legendary.exe` no repositorio).
- Em modo `tauri dev`, o Vite usa porta fixa `1420` (`strictPort` ativado).
- Auth local (SQLite) usa hash `Argon2id` para novas contas.
- Hash legado em `sha256` e migrado automaticamente para `Argon2id` no login valido.
- Rate limit de login local: ate 5 falhas em 5 minutos, com bloqueio temporario de 5 minutos.
- Sessao Supabase nao e persistida em texto no frontend; armazenamento usa secure store via backend Tauri.
